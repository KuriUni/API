端末認証ガイド

端末ごとの公開鍵で本人性を確認してから、ライセンスを認証します。秘密鍵は端末内に保管し、ライセンスキーと一緒にサーバーへ送らない方式です。

REST API · v3.0-beta1
01

端末鍵を用意

端末内でRSA鍵ペアを作成します。

02

チャレンジを取得

公開鍵を送り、一度限りの値を受け取ります。

03

端末内で署名

秘密鍵でチャレンジへ署名します。

04

認証して発行

署名とライセンス情報を送り、セッションを受け取ります。

認証前に用意するもの

V2のライセンスキーと端末IDだけの方式とは異なり、V3では端末鍵の署名が必要です。

license_keyproduct_code（任意）device_fingerprint（SHA-256 hex）RSA 2048 bit以上
!
秘密鍵は端末から出さない

秘密鍵はOSの安全な鍵保管領域へ保存してください。チャレンジ署名を作るときだけ端末内で使います。公開鍵と署名はAPIへ送信します。

1. チャレンジを取得する

端末で作成した公開鍵をPEM形式で送信します。チャレンジは短時間で失効し、一度だけ使用できます。

POST

端末鍵のチャレンジ

/license/api/v3/challenge.php
  • device_public_key
  • purpose: activate
curl -sS -X POST 'https://2415.jp/license/api/v3/challenge.php' \
  -H 'Content-Type: application/json' \
  -d '{
    "device_public_key": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n",
    "purpose": "activate"
  }'

応答例

{
  "success": true,
  "challenge": {
    "challenge_id": "発行されたID",
    "nonce": "一度限りの値",
    "purpose": "activate",
    "expires_at": "有効期限",
    "device_key_thumbprint": "公開鍵のSHA-256",
    "signature_algorithm": "RSA-SHA256"
  }
}

2. チャレンジへ署名する

次の文字列をUTF-8で署名します。行の順序と改行をそのまま保ち、最後に改行を追加しません。

TUTI-LICENSE-V3
activate
{challenge_id}
{nonce}
{device_key_thumbprint}

署名方式はRSA PKCS#1 v1.5 + SHA-256です。署名結果はBase64 URL-safe形式（末尾の = を省略）にします。鍵生成と署名処理はアプリ内の暗号ライブラリで行ってください。

3. ライセンスを認証する

チャレンジ取得時と同じ公開鍵を指定します。fingerprintは端末の安定した識別子から生成したSHA-256 hex値を使います。

POST

端末認証・セッション発行

/license/api/v3/activate.php
  • license_key
  • product_code
  • device_fingerprint
  • device_public_key
  • challenge_id
  • nonce
  • signature
  • device_label
  • app_version
curl -sS -X POST 'https://2415.jp/license/api/v3/activate.php' \
  -H 'Content-Type: application/json' \
  -d '{
    "license_key": "発行済みライセンスキー",
    "product_code": "製品コード",
    "device_fingerprint": "64桁のSHA-256 hex値",
    "device_public_key": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n",
    "challenge_id": "チャレンジ応答のID",
    "nonce": "チャレンジ応答のnonce",
    "signature": "端末内で作成したBase64URL署名",
    "device_label": "利用端末の表示名",
    "app_version": "1.0.0"
  }'
✓
認証成功時

ライセンス情報、端末参照情報、アクセストークンと更新トークンが返ります。トークンは秘密情報として安全に保管し、ログや画面共有に出さないでください。

応答とエラー

200 認証成功400 入力・署名形式エラー401 チャレンジ・署名不一致403 ライセンス無効・期限切れ409 端末数上限429 試行回数上限503 一時的なサービス障害

調査時は応答ヘッダーの X-Request-ID を記録してください。503応答には再試行の目安として Retry-After: 2 が付きます。成功したチャレンジ発行を含め、同一IPからの発行は15分間に60件までです。
