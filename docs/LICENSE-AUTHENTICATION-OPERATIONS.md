# ライセンス認証・セッション更新の運用

V2は既存クライアント向け、V3は端末公開鍵と署名による所持証明を使う認証APIです。既存の認証URL、トークン形式、HTTP応答の主要項目と有効期間は維持します。認証停止・失効・端末数制限の判定を省略して通信障害を回避する方式ではありません。

## V2の認証と更新

`POST /license/api/v2/activate.php` に `api_action` と必要な項目を送ります。`activate` はライセンスキーと端末情報、`verify` はアクセストークンと端末情報、`refresh` は更新トークンと端末情報を使います。

アクセストークンが期限切れでも、更新トークン・ライセンス・端末登録が有効なら `refresh` できます。更新トークンが期限切れ、使用済み、失効済みの場合は再利用できません。同時更新はライセンス、端末の順にロックし、同じ更新トークンで成功する要求を1回に限定します。更新後の両トークンを一緒に保存してください。更新応答を失い、手元に古いトークンしか残っていない場合は、ライセンスキーを使った再認証が必要になることがあります。

V2・V3をまたぐ端末数制限では、同じ端末を重複計上せず、有効なV3端末登録も含めて上限を検査します。期限切れV2行が残っていても、新しい端末として上限を回避できません。V3用の端末表がない環境ではV2の端末数を検査します。

## 更新時刻の目安

新規セッションと更新応答の `session` に、次の補助項目を返します。既存の有効期限項目も維持します。

| 項目 | 内容 |
| --- | --- |
| `server_time_utc` | 応答を作成したサーバー側のUTC時刻 |
| `access_expires_in` | アクセストークンの残り秒数 |
| `refresh_expires_in` | 更新トークンの残り秒数 |
| `refresh_after_seconds` | アクセス有効期間の約80%を目安にした更新開始時刻 |
| `token_version` | セッション更新の世代 |

ライセンスの有効期限を超えてトークンを延長しません。補助項目は期限や失効判定を無効化するものではありません。既存クライアントが自動的にこの目安を採用する変更ではなく、対応クライアントが利用するための情報です。

## V3の一括失効と制限

セッション失効の `scope: family` と更新トークン再利用検出では、同じfamilyのセッションとオフラインチケットのDBレコードをまとめて失効します。他のfamilyには影響しません。すでに端末へ配布されたチケットを完全オフラインで使う場合、失効を即時に通知できず、既存チケットの有効期限による制限が残ります。

チャレンジ発行は同一IPで15分間に60件までです。成功した発行も制限に含めます。端末署名の検証と使用済みトークンの検出は継続します。

## 障害時の判断と配備

DB・設定・内部処理の障害はHTTP 503と `SERVICE_UNAVAILABLE` を返し、`Retry-After: 2` を付けます。2秒後の復旧を保証するものではありません。利用者が入力を直す必要がある400系エラーと分けて判断してください。内部のDBエラーや秘密情報は応答へ含めません。応答本文の `request_id` とHTTPヘッダーの `X-Request-ID` を問い合わせ時に伝えてください。

PowerShell 7で `operations/Xrea/Deploy-LicenseAuthentication.ps1` を実行すると、保存済みDPAPI資格情報を使ってBackup、Primaryの順に対象ファイルだけを比較・配置します。配備前後のDBスナップショットは公開領域外へDPAPIで暗号化保存し、コードはSHA-256照合・失敗時の復元を行います。この改修の配備にDBスキーマ変更はありません。公開確認はトークン未指定などのエラー契約を使い、実在ライセンスの認証や失効は実行しません。
